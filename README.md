# Daily Agent

Личный рабочий помощник для macOS: повестка дня, встречи, задачи, чат с агентом.

Архитектура и план по шагам — в [`docs/architecture.md`](docs/architecture.md), макеты экранов — в [`docs/mockups/`](docs/mockups/).

Готовы шаги 1–4. Приложением можно пользоваться без агента:

- экран «Сегодня»: сводка, встречи на день с отсчётом до начала, «Входящие», «Бэклог»;
- встречи: список по дням («Предстоящие» на 14 дней, «Прошедшие» за 30 дней), карточка встречи, повтор, ссылки на созвон, кнопка «Подключиться»;
- задачи: «Входящие» (принять или отклонить), «Бэклог» (открытые и выполненные), свои задачи, карточка задачи, срок, заметка;
- теги: новый тег из боковой панели и из карточки, фильтр бэклога по тегу;
- ссылки задач и встреч: открываются в браузере по умолчанию, только `http` и `https`;
- поиск в боковой панели (⌘F) по названиям и заметкам задач и встреч.

С шага 3 приложение само запускает свой OpenCode и показывает его состояние в подвале боковой панели. С шага 4 есть чат с агентом:

- маленький чат — кнопка в правом нижнем углу на любом экране, кроме «Чатов». Новый чат получает агенду на сегодня: встречи и задачи;
- раздел «Чаты» — список переписок по дням, переименование и удаление;
- ответ агента приходит по мере готовности, его можно остановить;
- переписка хранится в базе OpenCode агента, в базе приложения — только ссылка на сессию и заголовок. После перезапуска история на месте.

Обновление данных из внешних систем и настройки появятся на следующих шагах.

### Как устроены повтор и поиск

- Повтор встречи хранится строкой в духе RRULE: `FREQ=DAILY`, `FREQ=WEEKLY;BYDAY=MO,TU,WE,TH,FR`, `FREQ=WEEKLY;INTERVAL=2`, `FREQ=MONTHLY`. Повторы считаются по местному времени. Изменение и удаление действуют на всю серию.
- Поиск — полнотекстовый индекс SQLite (FTS5). Ищет по началу слов, без учёта регистра, «ё» и «е» не различает. Падежей и других форм слова не понимает.

## Агент: OpenCode

Приложение запускает OpenCode **2.0.28** как дочерний процесс при старте и останавливает при выходе. Если OpenCode упал, надзор перезапускает его с паузой 1, 2, 4… до 60 секунд. Если приложение упало и OpenCode остался работать, следующий запуск завершает его по файлу PID.

Изоляция от обычной установки OpenCode:

- свои папки настроек, данных, кэша и рабочая папка: `~/Library/Application Support/Daily Agent/agent/` (переменные XDG и `TMPDIR` дочернего процесса);
- свой сервер `opencode serve` на `127.0.0.1`, свободный порт, случайный пароль на каждый запуск (HTTP Basic Auth);
- общая фоновая служба OpenCode, ваш `~/.config/opencode` и ваша база сессий не используются;
- OpenCode не загружает каталог моделей, не проверяет обновления, не ищет локальные модели и не читает настройки проектов из родительских папок.

Права агента ([`agent/opencode.base.json`](agent/opencode.base.json)):

- встроенные инструменты выключены как плагины: терминал, чтение, запись и правка файлов, запросы в сеть, поиск в интернете, субагенты, навыки;
- первое правило прав — «запретить всё» для агента приложения, для всех агентов и для каждой сессии, которую создаёт приложение;
- разрешённые инструменты (MCP-серверы источников, шаг 5) добавляются явно, после запрета;
- пользоваться можно только своим провайдером модели.

OpenCode ищется так: путь из `DAILY_AGENT_OPENCODE`, затем `~/.opencode/bin/opencode`, `PATH`, Homebrew. Подходит только версия 2.0.28. Состояние «OpenCode недоступен» в подвале значит, что такой версии нет; подробности — во всплывающей подсказке.

### Модель

До экрана настроек (шаг 7) модель задаётся при запуске приложения:

```bash
export DAILY_AGENT_MODEL_URL=…   # адрес API, совместимого с OpenAI, с /v1 на конце
export DAILY_AGENT_MODEL_ID=…    # идентификатор модели
```

Ключ хранится в Связке ключей. Команда спросит его сама, и он не попадёт в историю оболочки:

```bash
security add-generic-password -s "Daily Agent" -a "model-api-key" -w
```

В файлы настроек ключ не пишется: OpenCode получает его через переменную окружения своего процесса.

Для разработки есть заглушка модели на `127.0.0.1`, без сети:

```bash
DAILY_AGENT_STUB_MODEL=1 wails3 dev
```

### Проверка связи

```bash
wails3 task agent:check STUB=1   # с заглушкой модели
wails3 task agent:check N=10     # с настоящей моделью, запускает автор
```

Команда поднимает OpenCode с тем же профилем во временной папке, отправляет тестовый запрос и печатает только цифры: время запуска, время ответа, итог и число символов в ответе.

## Что нужно

| Инструмент | Версия |
| -- | -- |
| macOS | 13 или новее |
| Go | 1.26 или новее. В `go.mod` закреплён `toolchain go1.27.4` |
| Node и npm | Node 20.19 или новее |
| Инструменты командной строки Xcode | `xcode-select --install` |
| Wails CLI | v3.1.0 |
| OpenCode | 2.0.28 (для агента; без него приложение работает) |

Wails CLI ставится так:

```bash
GO111MODULE=on go install github.com/wailsapp/wails/v3/cmd/wails3@v3.1.0
```

Команда кладёт `wails3` в `~/go/bin`. Эта папка должна быть в `PATH`. Проверка окружения:

```bash
wails3 doctor
```

## Запуск в режиме разработки

```bash
wails3 dev
```

Команда ставит пакеты интерфейса, создаёт привязки TypeScript к сервисам на Go, собирает приложение и открывает окно. Правки интерфейса подхватываются сразу, правки Go — после пересборки.

## Тестовые данные

Данные вымышленные и похожи на макет «Сегодня». Даты считаются от текущего дня.

```bash
wails3 task db:seed          # наполнить пустую базу
wails3 task db:reset YES=1   # удалить все записи, схема останется
```

Обе команды работают с базой приложения. Другую базу можно указать через `DB=путь`, например `wails3 task db:seed DB=/tmp/dev.db`. Те же действия без Wails:

```bash
go run ./cmd/devdata seed [-db путь]
go run ./cmd/devdata reset -yes [-db путь]
```

`seed` отказывается работать с непустой базой, а `reset` — без подтверждения. Команды печатают только число записей.

## Где лежат данные

База — один файл SQLite: `~/Library/Application Support/Daily Agent/daily-agent.db`. Схема создаётся встроенными миграциями при запуске. Переменная окружения `DAILY_AGENT_DB` задаёт другой путь и действует и на приложение, и на команды выше.

## Сборка

```bash
wails3 build     # программа bin/daily-agent
wails3 package   # пакет bin/daily-agent.app с локальной подписью
```

## Тесты

```bash
go test ./...                  # ядро, без OpenCode и без сети
wails3 task test:integration   # с настоящим OpenCode 2.0.28 и заглушкой модели
```

Интеграционные тесты (`internal/agent`, `internal/app`) проверяют, что агент отвечает через заглушку и не может выполнить команду, создать или изменить файл. Ещё они проверяют чат: ответ приходит по частям, его можно остановить, история сохраняется после перезапуска OpenCode. Это верно даже для сессии с правами «разрешить всё». Ещё они проверяют, что настройки агента OpenCode принимает без предупреждений, а ваши `~/.config/opencode` и база сессий не меняются.

## Структура

| Папка | Что в ней |
| -- | -- |
| `main.go` | Запуск приложения, окно, подключение сервисов |
| `internal/store` | База, миграции (`migrations/*.sql`), запись, чтение и поиск |
| `internal/recur` | Повтор встреч: разбор правила и развёртка серии на промежуток |
| `internal/app` | Сервисы, которые вызывает окно: «Сегодня», боковая панель, встречи, задачи, теги, поиск, ссылки, агент и чат |
| `internal/devdata` | Тестовые данные и очистка базы |
| `cmd/devdata` | Команда `seed` / `reset` |
| `internal/agent` | Запуск OpenCode и надзор, клиент API и поток событий, модель и Связка ключей |
| `internal/agent/stubmodel` | Заглушка модели для разработки и тестов |
| `agent/` | Профиль агента: базовые настройки OpenCode и инструкции |
| `cmd/agentcheck` | Проверка связи с агентом |
| `frontend/` | Интерфейс на React и TypeScript; `src/styles/tokens.css` — цвета, отступы и размеры |
| `frontend/bindings/` | Привязки к сервисам. Создаются командой `wails3 generate bindings`, вручную не правятся |
| `build/` | Настройки сборки и пакетов Wails |
| `docs/` | Архитектура и макеты |
