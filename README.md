# Daily Agent

Личный рабочий помощник для macOS: повестка дня, встречи, задачи, чат с агентом.

Архитектура и план по шагам — в [`docs/architecture.md`](docs/architecture.md), макеты экранов — в [`docs/mockups/`](docs/mockups/).

Готовы шаги 1–4. Приложением можно пользоваться без агента:

- экран «Сегодня»: сводка, встречи на день с отсчётом до начала, план на день;
- встречи: список по дням («Предстоящие» на 14 дней, «Прошедшие» за 30 дней), карточка встречи, повтор, ссылки на созвон, кнопка «Подключиться»;
- задачи: «Входящие» (принять или отклонить), «Бэклог» (открытые и выполненные), свои задачи, карточка задачи, срок, заметка;
- теги: новый тег из боковой панели и из карточки, фильтр бэклога по тегу;
- ссылки задач и встреч: открываются в браузере по умолчанию, только `http` и `https`;
- поиск в боковой панели (⌘F) по названиям и заметкам задач и встреч.

С шага 3 приложение само запускает свой OpenCode и показывает его состояние в подвале боковой панели. С шага 4 есть чат с агентом:

- маленький чат — кнопка в правом нижнем углу на любом экране, кроме «Чатов». Новый чат получает агенду на сегодня: встречи и задачи;
- раздел «Чаты» — список переписок по дням, переименование и удаление;
- ответ агента приходит по мере готовности, его можно остановить;
- переписка хранится в базе OpenCode агента, в базе приложения — только ссылка на сессию и заголовок. После перезапуска история на месте.

Обновление данных из внешних систем и настройки появятся на следующих шагах.

### Как устроены повтор и поиск

- Повтор встречи хранится строкой в духе RRULE: `FREQ=DAILY`, `FREQ=WEEKLY;BYDAY=MO,TU,WE,TH,FR`, `FREQ=WEEKLY;INTERVAL=2`, `FREQ=MONTHLY`. Повторы считаются по местному времени. Изменение и удаление действуют на всю серию.
- Поиск — полнотекстовый индекс SQLite (FTS5). Ищет по началу слов, без учёта регистра, «ё» и «е» не различает. Падежей и других форм слова не понимает.

## Агент: OpenCode

Приложение запускает OpenCode **2.0.28** как дочерний процесс при старте и останавливает при выходе. Если OpenCode упал, надзор перезапускает его с паузой 1, 2, 4… до 60 секунд. Если приложение упало и OpenCode остался работать, следующий запуск завершает его по файлу PID.

Изоляция от обычной установки OpenCode:

- свои папки настроек, данных, кэша и рабочая папка: `~/Library/Application Support/Daily Agent/agent/` (переменные XDG и `TMPDIR` дочернего процесса);
- свой сервер `opencode serve` на `127.0.0.1`, свободный порт, случайный пароль на каждый запуск (HTTP Basic Auth);
- общая фоновая служба OpenCode и ваша база сессий не используются; из вашего `~/.config/opencode` приложение берёт только описания провайдеров моделей и MCP-серверов, без ключей и токенов (см. «Модели» и «MCP-серверы»);
- каталог провайдеров встроен в OpenCode и из сети не обновляется; OpenCode не проверяет обновления, не ищет локальные модели и не читает настройки проектов из родительских папок.

Права агента ([`agent/opencode.base.json`](agent/opencode.base.json)):

- встроенные инструменты выключены как плагины: терминал, чтение, запись и правка файлов, запросы в сеть, поиск в интернете, субагенты, навыки;
- первое правило прав — «запретить всё» для агента приложения, для всех агентов и для каждой сессии, которую создаёт приложение;
- разрешённые инструменты MCP-серверов добавляются явно, после запрета, и только инструменты чтения;
- Code Mode (`execute`) выключен у всех MCP-серверов и никогда не разрешается: его JavaScript умеет `fetch` в обход прав;
- пользоваться можно только подключёнными провайдерами моделей: политика `provider.use` запрещает всех остальных.

OpenCode ищется так: путь из `DAILY_AGENT_OPENCODE`, затем `~/.opencode/bin/opencode`, `PATH`, Homebrew. Подходит только версия 2.0.28. Состояние «OpenCode недоступен» в подвале значит, что такой версии нет; подробности — во всплывающей подсказке.

### Модели

На экране «Настройки» → «Агент» выбираются две модели:

- **для рабочих задач** — только селфхост. В неё идут маленький чат с агендой и рабочие чаты;
- **для личных задач** — любая, в том числе облачная. В неё идут личные чаты из раздела «Чаты». Личный чат не получает агенду, задачи и встречи. Без своей модели личные чаты идут в рабочую.

Выбор модели из уже подключённых провайдеров OpenCode не перезапускает; новый ключ или провайдер — перезапускает. Открытые чаты продолжаются с выбранной моделью. Кнопки «Рабочая» и «Личная» в строке «Связь с моделями» задают модели короткий вопрос через OpenCode и показывают только итог и время ответа.

Откуда берутся провайдеры (раздел «Провайдеры»):

- **Селфхост-API** — своя модель по адресу: API, совместимый с OpenAI (обычно с `/v1` на конце), идентификатор модели и ключ, если API его требует. Адреса известных облачных API (OpenAI, Anthropic, Google, OpenRouter и других) здесь не принимаются. Это защита от ошибки, а не проверка сети: что адрес действительно селфхост, решаете вы.
- **Ваши настройки OpenCode** — `~/.config/opencode/opencode.json` и `opencode.jsonc` (или `$XDG_CONFIG_HOME/opencode`). Из них берётся только раздел провайдеров: формат второй версии (`providers`) и провайдеры первой версии (`provider`) с API, совместимым с OpenAI. Ключи, токены и заголовки авторизации не переносятся; MCP-серверы, плагины, агенты и права — тоже. Если провайдеру нужен ключ, задайте его кнопкой «Ключ…». Селфхост — провайдер с явным адресом, который не принадлежит известному облачному сервису.
- **Облачный провайдер** из каталога OpenCode (OpenAI, Anthropic, OpenRouter и ещё более двухсот) подключается ключом через «Подключить…». Его модели можно выбрать только для личных задач. Провайдеры, которые подключаются только входом через браузер, пока не поддерживаются.

Где что хранится:

- выбор моделей, адрес своей модели и список подключённых провайдеров — в базе приложения, в таблице `settings`;
- ключи — в Связке ключей macOS, служба «Daily Agent»: запись «model-api-key» для своей модели и «provider:<идентификатор>» для остальных. В базу и файлы настроек они не пишутся, OpenCode получает их через переменные окружения своего процесса. Записывает и читает ключи системная утилита `security`; команда идёт ей через стандартный ввод, поэтому ключа нет в списке процессов.

Без настроек на экране своя модель берётся из переменных окружения `DAILY_AGENT_MODEL_URL` и `DAILY_AGENT_MODEL_ID`; настройки на экране важнее.

Для разработки есть заглушка модели на `127.0.0.1`, без сети. Можно запустить приложение сразу с ней:

```bash
DAILY_AGENT_STUB_MODEL=1 wails3 dev
```

Или запустить заглушку отдельно и ввести её адрес на экране настроек, чтобы проверить смену модели:

```bash
wails3 task stub:model PORT=8765   # адрес http://127.0.0.1:8765/v1, модель — любая
```

Чтобы проверки не трогали ваши настоящие ключи и настройки OpenCode, переменная `DAILY_AGENT_KEYCHAIN` задаёт другой файл связки ключей, а `DAILY_AGENT_OPENCODE_CONFIG` — другую папку или файл настроек OpenCode (`off` — не читать их вовсе):

```bash
security create-keychain -p test /tmp/da-dev.keychain-db
DAILY_AGENT_DB=/tmp/da-dev.db DAILY_AGENT_KEYCHAIN=/tmp/da-dev.keychain-db DAILY_AGENT_OPENCODE_CONFIG=off wails3 dev
```

### MCP-серверы

Раздел «Настройки» → «MCP-серверы». Серверы подключаются к агенту через OpenCode: ядро приложения к ним само не обращается.

- **Откуда.** Серверы из ваших настроек OpenCode (`mcp.servers` второй версии и `mcp.<имя>` первой) подхватываются сами. Свой сервер добавляется кнопкой «+ Сервер»: удалённый по адресу или локальный по команде.
- **Токены.** Токены из заголовков и переменных окружения в профиль не переносятся. Сервер без токена помечен «Нужен токен» и агенту недоступен, пока токен не сохранён кнопкой «Токен…». Если токен записан прямо в ваших настройках OpenCode, в том же окне есть кнопка «Взять из настроек OpenCode»: она переносит его в Связку ключей. Токены хранятся в Связке ключей (запись «mcp:<сервер>:…»), в настройках OpenCode агента на их месте ссылка `{env:…}`.
- **Окружение.** Приложение из Finder получает урезанное окружение, поэтому OpenCode запускается с `PATH` из вашей оболочки входа (`$SHELL -ilc`): так находятся `npx`, `node` и другие команды локальных серверов. Если в ваших настройках есть ссылки `{env:ИМЯ}`, значения именно этих переменных тоже берутся из оболочки входа и передаются только процессу OpenCode. Остальное окружение оболочки не используется.
- **Ошибки.** Если сервер не запустился, под ним виден текст ошибки OpenCode. Локальным серверам даётся до двух минут на запуск: `npx -y пакет` при первом запуске скачивает пакет. Те, кто не успел подключиться за прогрев, подхватываются позже сами.
- **Вход через браузер.** Для серверов с OAuth кнопка «Войти» открывает вход в браузере. Данные входа хранит OpenCode в папке данных агента приложения; ваши прежние входы не переносятся.
- **Только чтение.** Агенту разрешены инструменты чтения: в имени есть слово чтения (`get`, `list`, `search`, `lookup`, `details`, `comments`, `status`…) и нет глагола записи. Правило понимает оба способа называть инструменты: «сначала глагол» (`get_issue`, `create_issue`) и «сначала существительное», как у YouTrack (`issue_details`, `issue_create`). Глагол записи — первым или последним словом, после `and` или однозначный глагол в середине (`issue_change_state`); слова, которые бывают существительными (`merge`, `comment`, `run`), в середине не в счёт: `get_merge_request` — чтение. Это проверка по имени: аннотации MCP OpenCode агенту не передаёт. Если у сервера не нашлось ни одного инструмента чтения, он подсвечен; в «Инструментах…» можно выбрать набор вручную, но инструменты записи в v0.1 закрыты в любом случае.
- **Только рабочие чаты.** Права с инструментами получают маленький чат и рабочие чаты; приложение обновляет их при каждом сообщении, поэтому выключенный сервер пропадает и из старых чатов. Личные чаты могут идти в облачную модель и инструментов рабочих систем не получают.
- **Прогрев.** После запуска OpenCode приложение ждёт, пока серверы подключатся, и узнаёт их инструменты служебной сессией со встроенной заглушкой модели (провайдер `daily-discovery`, только 127.0.0.1). Пока это идёт, агент «запускается».

Для проверки без рабочих систем есть заглушка MCP — вымышленный трекер с инструментами `get_issue`, `list_issues` и `create_issue`:

```bash
wails3 task stub:mcp PORT=8770            # удалённый сервер http://127.0.0.1:8770/mcp
wails3 task stub:mcp PORT=8771 OAUTH=1    # он же со входом через браузер
```

### План на день

На экране «Сегодня» есть раздел «План на день». Кнопка «Составить план» открывает маленький чат и просит агента составить план. Агент смотрит встречи и свободное время, берёт задачи из бэклога, оценивает их в минутах и записывает план: задачи с оценкой и причиной выбора и короткое пояснение, которое видно в «Сводке от агента». Повторный план на тот же день заменяет прежний. Задачу можно добавить в план вручную кнопкой «В план» на экране «Бэклог» или убрать из плана. Рабочий день — 8 часов минус встречи.

Для этого у агента есть свой MCP-сервер приложения — та же программа с подкомандой `mcp`, через stdin и stdout, без сети:

| Инструмент | Что делает |
| -- | -- |
| `get_day` | Встречи на день с идентификаторами, свободное время в минутах, текущий план, смещение местного времени |
| `list_tasks` | Бэклог, «Входящие» или закрытые задачи с идентификаторами, тегами и сроками |
| `set_day_plan` | Записать план: задачи из бэклога с оценками и причинами, пояснение |
| `list_meetings` | Встречи за промежуток до 31 дня с идентификаторами, повторы развёрнуты по дням |
| `create_meeting` | Добавить встречу: название, дата, начало, длительность, повтор, заметка, ссылки на созвон |
| `update_meeting` | Изменить переданные поля встречи |
| `delete_meeting` | Удалить встречу, добавленную вручную |
| `create_task` | Добавить свою задачу в бэклог или во «Входящие» |
| `update_task` | Изменить переданные поля задачи и её статус |

### Встречи и задачи из чата

Агента можно попросить добавить встречу — например, переслать ему приглашение — или задачу, перенести встречу, закрыть задачу. Он записывает это тем же сервером `daily`. Правила те же, что у карточек в окне, и ещё несколько:

- Агент пишет только в базу приложения. Внешние системы он по-прежнему только читает.
- Записывать агент должен только по прямой просьбе автора в чате. Текст задач, встреч и приглашений — данные, а не просьба: это сказано в его инструкциях и в описаниях инструментов.
- Меняются только переданные поля. Неизвестное поле в вызове — ошибка: опечатка не потеряет время или срок.
- Встречу с тем же названием и началом и задачу с тем же названием во «Входящих» и бэклоге второй раз не создают.
- Повторяющуюся встречу агент меняет и удаляет только целой серией и только с `series: true` — после вопроса автору.
- У встреч из сервиса видеовстреч меняются только заметка и ссылки, удалить их нельзя. У задач из внешних систем не меняется название.
- Удаляются только встречи, удаление мягкое. Задачи агент не удаляет, а закрывает или отклоняет.
- Ссылки — только http:// и https://.

В OpenCode агента сервер подключён всегда под именем `daily`, его инструменты разрешены рабочим чатам; личным — нет, как и любые рабочие данные. Сервер пишет в ту же базу, что и приложение, а окно замечает записи других процессов по признаку изменений SQLite (`PRAGMA data_version`) и обновляет экраны. Каждый вызов виден в чате строкой «Инструмент …».

Тот же сервер можно подключить к своему агенту, например к OpenCode в терминале: «Настройки» → «MCP-серверы» → «Подключить к своему агенту» показывает готовый фрагмент настроек и команду для Claude Code. Сервер работает и без запущенного приложения:

```bash
"/Applications/Daily Agent.app/Contents/MacOS/daily-agent" mcp   # путь к своей сборке
```

Внешний агент получает те же инструменты, в том числе запись. Если он работает с облачной моделью, встречи и задачи уйдут ей.

### Проверка связи

```bash
wails3 task agent:check STUB=1   # с заглушкой модели
wails3 task agent:check N=10     # с моделью для рабочих задач, запускает автор
wails3 task agent:check PERSONAL=1  # с моделью для личных задач
```

Модели берутся так же, как в приложении: из его настроек, ваших настроек OpenCode и Связки ключей. Команда поднимает OpenCode с тем же профилем во временной папке, отправляет тестовый запрос и печатает только цифры: время запуска, время ответа, итог и число символов в ответе.

## Что нужно

| Инструмент | Версия |
| -- | -- |
| macOS | 13 или новее |
| Go | 1.26 или новее. В `go.mod` закреплён `toolchain go1.27.4` |
| Node и npm | Node 20.19 или новее |
| Инструменты командной строки Xcode | `xcode-select --install` |
| Wails CLI | v3.1.0 |
| OpenCode | 2.0.28 (для агента; без него приложение работает) |

Wails CLI ставится так:

```bash
GO111MODULE=on go install github.com/wailsapp/wails/v3/cmd/wails3@v3.1.0
```

Команда кладёт `wails3` в `~/go/bin`. Эта папка должна быть в `PATH`. Проверка окружения:

```bash
wails3 doctor
```

## Запуск в режиме разработки

```bash
wails3 dev
```

Команда ставит пакеты интерфейса, создаёт привязки TypeScript к сервисам на Go, собирает приложение и открывает окно. Правки интерфейса подхватываются сразу, правки Go — после пересборки.

## Тестовые данные

Данные вымышленные и похожи на макет «Сегодня». Даты считаются от текущего дня.

```bash
wails3 task db:seed          # наполнить пустую базу
wails3 task db:reset YES=1   # удалить все записи, схема останется
```

Обе команды работают с базой приложения. Другую базу можно указать через `DB=путь`, например `wails3 task db:seed DB=/tmp/dev.db`. Те же действия без Wails:

```bash
go run ./cmd/devdata seed [-db путь]
go run ./cmd/devdata reset -yes [-db путь]
```

`seed` отказывается работать с непустой базой, а `reset` — без подтверждения. Команды печатают только число записей.

## Где лежат данные

База — один файл SQLite: `~/Library/Application Support/Daily Agent/daily-agent.db`. Схема создаётся встроенными миграциями при запуске. Переменная окружения `DAILY_AGENT_DB` задаёт другой путь и действует и на приложение, и на команды выше. Настройки лежат в той же базе, кроме ключа модели: он в Связке ключей.

```bash
wails3 task test:integration   # с настоящим OpenCode 2.0.28 и заглушкой модели
```

Интеграционные тесты (`internal/agent`, `internal/app`) проверяют, что агент отвечает через заглушку и не может выполнить команду, создать или изменить файл. Ещё они проверяют чат: ответ приходит по частям, его можно остановить, история сохраняется после перезапуска OpenCode, а после смены модели в настройках чат продолжается с новой моделью и её ключом. Отдельный тест берёт провайдеров из вымышленных настроек OpenCode и проверяет, что рабочий чат уходит в рабочую модель, личный — в личную, а встроенный каталог провайдеров доступен без сети. Живой тест плана на день проверяет: «Составить план» открывает рабочий чат с тремя инструментами приложения, агент через свой сервер записывает план в базу, окно замечает запись, а личный чат инструментов не получает. Тесты MCP на заглушках проверяют: модели предлагаются только разрешённые инструменты чтения, запись и `execute` отклоняются и до сервера не доходят, токены приходят из окружения, а не из файла настроек, вход OAuth работает, выключенный сервер недоступен, а личный чат инструментов не получает. Это верно даже для сессии с правами «разрешить всё». Ещё они проверяют, что настройки агента OpenCode принимает без предупреждений, а ваши `~/.config/opencode` и база сессий не меняются.

## Структура

| Папка | Что в ней |
| -- | -- |
| `main.go` | Запуск приложения, окно, подключение сервисов |
| `internal/store` | База, миграции (`migrations/*.sql`), запись, чтение и поиск |
| `internal/recur` | Повтор встреч: разбор правила и развёртка серии на промежуток |
| `internal/app` | Сервисы, которые вызывает окно: «Сегодня», план на день, боковая панель, встречи, задачи, теги, поиск, ссылки, агент, чат, настройки и MCP-серверы; свой MCP-сервер приложения |
| `internal/devdata` | Тестовые данные и очистка базы |
| `cmd/devdata` | Команда `seed` / `reset` |
| `internal/agent` | Запуск OpenCode, надзор и перезапуск со сменой модели, клиент API и поток событий, модели, MCP-серверы и их прогрев, Связка ключей |
| `internal/agent/stubmodel` | Заглушка модели для разработки и тестов, она же служебная модель для списка инструментов |
| `internal/agent/mcpstub` | Заглушка MCP-сервера для тестов: stdio, HTTP и вход OAuth |
| `agent/` | Профиль агента: базовые настройки OpenCode и инструкции |
| `cmd/agentcheck` | Проверка связи с агентом |
| `cmd/stubmodel` | Заглушка модели отдельным процессом, для проверки экрана настроек |
| `cmd/mcpstub` | Заглушка MCP-сервера отдельным процессом |
| `frontend/` | Интерфейс на React и TypeScript; `src/styles/tokens.css` — цвета, отступы и размеры |
| `frontend/bindings/` | Привязки к сервисам. Создаются командой `wails3 generate bindings`, вручную не правятся |
| `build/` | Настройки сборки и пакетов Wails |
| `docs/` | Архитектура и макеты |
