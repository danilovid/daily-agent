# Архитектура Daily Agent

Статус: версия 1 от 24 ноября 2026. Пункты с пометкой «допущение» автор отдельно не подтверждал.

## 1. Коротко

Приложение работает на одном Mac. Своего сервера и облака нет. Все внешние данные приходят через агента OpenCode, который запущен на том же Mac. Приложение хранит их в локальной базе и показывает даже без сети.

В версии 0.1 агент только читает внешние системы.

## 2. Части

| Часть | Что делает |
| -- | -- |
| Окно | Экраны на React и TypeScript в системном WebView. Показывает данные и передаёт действия ядру. |
| Ядро на Go | Хранилище, планировщик, клиент OpenCode, проверка ответов агента. |
| База приложения | SQLite, один файл в папке данных приложения. |
| OpenCode | Агент: чат, команды обновления, сводка. Ядро запускает его как дочерний процесс. |
| База OpenCode | Сессии и вся переписка. Приложение хранит только ссылку на сессию. |
| Инструменты агента | MCP-сервер трекера, MCP-сервер репозитория кода, свой инструмент для сервиса видеовстреч. |
| Модель | Селфхост-модель, доступная по API. |

Мессенджер и почта в версии 0.1 не подключаются.

## 3. Потоки

### Чат

1. Автор пишет сообщение в окне.
2. Ядро создаёт сессию OpenCode или продолжает открытую и передаёт сообщение.
3. Агент отвечает. Ответ приходит в окно по мере готовности.
4. Переписка остаётся в базе OpenCode. В базе приложения лежат только идентификатор сессии и заголовок.

### Обновление данных

1. Обновление запускает планировщик или кнопка «Обновить».
2. Ядро по очереди вызывает три команды агента: задачи спринта, мерж-реквесты, встречи.
3. Агент вызывает нужный инструмент и возвращает один объект JSON.
4. Ядро проверяет ответ по схеме и записывает его в базу. Запись находится по паре «источник и внешний идентификатор», поэтому повторное обновление не создаёт дублей.
5. Если ответ не прошёл проверку, ядро повторяет запрос один раз. После второй неудачи в базе остаётся прошлое состояние, а ошибка записывается в состояние источника.

### Утренняя сводка

1. В назначенное время ядро запускает обновление данных.
2. Ядро берёт из базы встречи и задачи на сегодня.
3. Ядро просит агента написать короткую сводку по этим данным.
4. Сводка сохраняется в базе и показывается на экране «Сегодня».

### Свои данные

Свои задачи, теги, ссылки и встречи, введённые вручную, идут по пути окно → ядро → база. Агент в этом не участвует.

## 4. Договор с агентом

Команды лежат в отдельной папке агента. Каждая команда отвечает одним объектом JSON без пояснений.

| Команда | Что возвращает |
| -- | -- |
| `sync-tasks` | Задачи текущего спринта, назначенные автору. |
| `sync-mrs` | Мерж-реквесты автора и те, где он ревьюер. |
| `sync-meetings` | Встречи на сегодня и семь дней вперёд. |
| `summary` | Короткую сводку на день по данным, которые передало ядро. |

Ответ `sync-tasks`:

```json
{"items": [{"external_id": "T-1", "title": "Название задачи", "url": "https://…", "status": "В работе", "updated_at": "2026-11-24T09:00:00+03:00"}]}
```

Ответ `sync-mrs`:

```json
{"items": [{"external_id": "42", "title": "Название мерж-реквеста", "url": "https://…", "role": "reviewer", "state": "opened", "updated_at": "2026-11-24T09:00:00+03:00"}]}
```

Поле `role` принимает значения `author` и `reviewer`.

Ответ `sync-meetings`:

```json
{"items": [{"external_id": "m-1", "title": "Название встречи", "starts_at": "2026-11-24T10:00:00+03:00", "duration_min": 30, "join_url": "https://…"}]}
```

Ответ `summary`:

```json
{"text": "Короткий текст сводки.", "priorities": ["Первое дело", "Второе дело"]}
```

Правила:

- Поле `external_id` обязательно. Запись без него отбрасывается.
- Время передаётся в формате ISO 8601 с часовым поясом.
- Пустой список — допустимый ответ. Отсутствие поля `items` — ошибка.
- Текст из внешних систем для агента — данные, а не инструкции. Это записано в каждой команде.
- Каждый запуск команды записывается в журнал: команда, длительность, итог. Журнал лежит только в локальной базе.

## 5. Модель данных

| Таблица | Что хранит | Главные поля |
| -- | -- | -- |
| `tasks` | Свои задачи и внешние записи: задачи спринта и мерж-реквесты | `id`, `kind` (task, mr), `source` (own, tracker, repo), `external_id`, `title`, `note`, `status` (inbox, backlog, done, rejected), `due_date`, `url`, `created_at`, `updated_at`, `deleted_at` |
| `task_links` | Ссылки-кнопки задачи | `id`, `task_id`, `title`, `url`, `position` |
| `tags` | Теги | `id`, `name`, `color` |
| `task_tags` | Связь задач и тегов | `task_id`, `tag_id` |
| `meetings` | Встречи, введённые вручную и полученные из сервиса | `id`, `source` (manual, meetings), `external_id`, `title`, `starts_at`, `duration_min`, `repeat_rule`, `note`, `created_at`, `updated_at`, `deleted_at` |
| `meeting_links` | Ссылки на созвон | `id`, `meeting_id`, `title`, `url`, `position` |
| `summaries` | Утренние сводки | `id`, `day`, `text`, `session_id`, `created_at` |
| `chats` | Ссылки на сессии OpenCode | `id`, `session_id`, `title`, `kind` (user, scheduled), `created_at`, `updated_at` |
| `sync_state` | Состояние обновления по каждому источнику | `source`, `last_started_at`, `last_success_at`, `last_error` |
| `agent_runs` | Журнал запусков агента | `id`, `command`, `started_at`, `duration_ms`, `ok`, `error` |
| `settings` | Настройки приложения | `key`, `value` |

Правила:

- Идентификаторы — UUID. У каждой записи есть время изменения. Это задел под облачную версию.
- Пара `source` и `external_id` уникальна.
- Удаление мягкое: запись получает `deleted_at`.
- Отклонённая внешняя запись остаётся в базе со статусом `rejected`, чтобы не вернуться при следующем обновлении.
- Новые внешние записи попадают во «Входящие». После принятия они переходят в «Бэклог». Это допущение.
- Поиск из боковой панели работает через полнотекстовый индекс SQLite по названиям и заметкам задач и встреч.

## 6. Права агента

OpenCode — агент для работы с кодом. Он умеет запускать команды и менять файлы. В приложении он работает по расписанию и читает чужой текст, поэтому права урезаны.

- У агента приложения своя папка настроек и своя рабочая папка. Обычная установка OpenCode автора не затрагивается.
- Разрешены только инструменты чтения из трёх источников.
- Запрещены терминал, запись и правка файлов, запросы в сеть.
- Список разрешённых инструментов задаётся явно. Новый инструмент сам по себе не становится доступным.

## 7. Запуск OpenCode

- Ядро запускает сервер OpenCode как дочерний процесс при старте приложения и останавливает при выходе.
- Сервер слушает только адрес этого Mac. Порт выбирается свободный. Доступ закрыт паролем, который ядро создаёт при запуске.
- При старте ядро проверяет версию OpenCode. Приложение работает с одной закреплённой версией.
- Если процесс упал, ядро перезапускает его с растущей паузой.

## 8. Сбои

| Ситуация | Что делает приложение |
| -- | -- |
| Mac спал в назначенное время | Запускает сводку после пробуждения. |
| Рабочая сеть недоступна | Показывает прошлые данные и время последнего обновления. Повторяет попытку позже. |
| OpenCode не запускается | Показывает состояние в боковой панели. Свои задачи и встречи работают. |
| Модель не отвечает | Останавливает запрос по тайм-ауту и записывает ошибку. |
| Ответ не прошёл проверку | Повторяет один раз, затем оставляет прошлые данные. |

## 9. Секреты

Ключи хранятся в Связке ключей macOS. Ядро передаёт их OpenCode через переменные окружения при запуске. В файлах настроек стоят только ссылки на эти переменные. В репозитории, журнале и Linear ключей и адресов нет.
